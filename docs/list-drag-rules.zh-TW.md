# List 拖曳、落點與預覽動畫規則

本文記錄目前的實作行為與維護原則。調整落點、間距或動畫時，請同步更新本文與測試。

## 1. 名詞與操作目標

- **Board（看板）**：包含所有欄與列表的畫面；本功能移動的不是 Board。
- **Column（欄）**：水平方向排列的群組，每欄可放一個或多個 List。
- **List（列表）**：例如 `dssa`、`222`、`333`，同欄內由上而下排列。
- **結合（merge）**：將 List 放入既有欄，不是合併列表內容或卡片。
- **插入（insert）**：將 List 作為獨立欄，放在最左、兩欄之間或最右。

不要求使用者對準額外的可見放置區。拖動時，其他列表先預覽放開後的位置；放開後保存相同的排列。

## 2. 位置如何取得

拖曳開始時，以各 List 的 `getBoundingClientRect()` 建立幾何快照，記錄原始位置、寬度、高度及欄順序。拖曳期間透過 `requestAnimationFrame` 持續讀取被拖動 List 的 DOM 矩形：

```js
top_middle_x = rect.left + rect.width / 2 + window.scrollX;
top_y = rect.top + window.scrollY;
bottom_y = rect.bottom + window.scrollY;
```

- 使用的是 **List 元件頂邊中點**，不是滑鼠游標，也不是元件垂直中心。
- 加上頁面捲動量後，統一以文件座標比較。
- `top_middle_x` 決定要加入哪一欄，或在哪裡新增欄。
- `top_y` 決定同欄內的上下插入順序。
- `bottom_y` 目前只參與有效範圍判斷，**不作為上下排序錨點**。
- 其他列表始終使用拖曳開始的快照，不重新量測已被預覽動畫推動的目標，避免落點反覆跳動。

## 3. 有效範圍

每一幀須同時符合以下條件，才計算落點：

- `bottom_y >=` 拖曳開始時的看板內容頂邊。
- `rect.top < window.innerHeight`。
- 元件水平中心在視窗的 `0` 到 `window.innerWidth` 之間（含邊界）。

因此，List 頂邊略高於看板仍可排序，只要底邊尚未離開看板頂邊。無效時清除落點與位移預覽；若放開前最後一次判定無效，就不保存移動。

這是目前的邊界檢查，並非完整的看板矩形碰撞判定。

## 4. X 軸：結合或插入新欄

以原始幾何快照建立下列候選位置，選取與 `top_middle_x` 水平距離最近者：

| 候選位置 | X 座標 | 意義 |
| --- | --- | --- |
| 每欄中心 | `column.left + column.width / 2` | 加入該欄，再判定上下順序 |
| 每欄左側 | `column.left - 8` | 在該欄之前插入獨立欄 |
| 最後一欄右側 | `last.left + last.width + 8` | 在最右側插入獨立欄 |

目前 List 寬度為 `272px`，相鄰 List 左緣相差 `288px`，所以兩欄間候選位置位於 `16px` 間隔的中點。這是「最近候選位置」判定，不是只有游標進入細縫才能插入；插入模式本身不依 Y 軸區分。

防抖規則：若舊候選距離不超過新候選距離加 `12px`，保留舊候選。這個 `12px` 是**距離差容忍值**，不是可見放置區寬度。沒有舊候選且距離相同時，保留候選陣列中較早的一個。

## 5. Y 軸：同欄上下排序

選定結合欄後：

1. 從該欄的判定列表排除被拖動的 List，避免自己與自己比較。
2. 依原始上下順序，找出第一個滿足 `拖動 top_y < 目標 top + 目標 height / 2` 的列表。
3. 插在該列表之前；若全部都不符合，放在欄底。

也就是說，拖動物件頂邊位於目標列表上半部時排在它之前；到達目標中線或下半部時排在它之後，再繼續比較後面的列表。不同高度的列表使用各自的中線；不受拖動物件自身高度影響。

這是最初「接近目標頂邊／底邊」需求的具體實作：以**目標中線切分前後**，沒有另外設置頂邊／底邊吸附距離。此規則同時適用於跨欄加入與同欄上下交換。

## 6. 排列投影與來源欄處理

預覽與真正放開共用 `projectLayout`，處理順序不可分歧：

1. 先移除來源 List。
2. 移除因此變空的來源欄；若來源欄還有其他 List，就保留。
3. 結合時，將來源 List 放進目標欄指定的上下索引。
4. 插入時，依「原插入點之前、且移除來源後仍存在的欄」數量，換算新索引，再建立獨立欄。

**不可直接沿用移除來源前的數字索引**，否則向右拖曳可能落到目標左側。

例：原排列為 `[333] [dssa, 222]`（逗號表示同欄上下順序）：

- 將 `222` 拉到最右側 → `[333] [dssa] [222]`。
- 將 `222` 拉到兩欄之間 → `[333] [222] [dssa]`。
- 將 `222` 拉到 `dssa` 上半部 → `[333] [222, dssa]`。

單列表欄回到原本槽位時，不新增空間，也不推開後面的欄。同欄且上下索引不變時，不送出更新。

## 7. 放開前的讓位動畫

- 以投影排列計算每個非拖動 List 相對於快照的 `x/y` 位移。
- 水平每欄前進 `List 寬度 + 16px`；垂直每列表前進 `列表高度 + 8px`。
- 從看板內容頂邊向下排列，以 `translate(x, y)` 及 `transform 150ms ease-out` 顯示讓位。
- 被拖動的 List 保留拖曳套件提供的樣式，不套用其他列表的預覽位移。
- 預覽期間固定各列表外層的原始高度，並隱藏套件的 placeholder，避免雙重占位。
- 插入新欄時，插入點後方的欄依最終投影讓位；結合時，目標欄內的列表依上下位置讓位。
- 來源欄變空也會影響排列，因此不是每次插入都一律把右側再推一欄；**以投影後的實際位置差為準**。

預覽只改顯示，不在每一幀寫入資料庫，也不修改原始幾何快照。

## 8. 放開、取消與回彈動畫

在 `window` 的捕獲階段監聽 `mouseup`／`touchend`，立刻標記拖曳已放開並停止幀更新，鎖定**最後已計算並預覽的落點**。目前不是在放開事件內額外量測一次 DOM。

之後 `onDragEnd` 使用鎖定結果保存排列，不能改用套件回彈動畫途中的矩形重新判定。先前「預覽插入，放開卻結合」的原因，就是回彈動畫把自訂落點覆蓋了。

- 只有結束原因為 `DROP` 才可保存。
- Escape 等取消操作只清除預覽，不更新排列。
- 無有效落點、或回到原位置時，不更新排列。
- 結束時清除動畫、拖曳狀態與預覽位移。

## 9. 保存欄與列表順序

目前欄由 List 的資料分組，不是獨立的 Column 資料表：

| 欄位 | 用途 |
| --- | --- |
| `columnId` | 相同值的 List 顯示於同欄；缺少時使用 List 自己的 `id` |
| `columnPosition` | 欄的水平排序；缺少時退回 List 的 `position` |
| `position` | List 在欄內的上下排序 |

顯示時，同欄的水平排序值取各 List 回退後數值的最小值；欄內以 `position` 排序。數值相同時以 ID 字串排序，保持順序確定。

- 加入既有欄：沿用目標 `columnId` 與欄排序值。
- 從多列表欄拆出：建立新的 `column:<listId>:<時間戳>` 識別值。
- 移動整個單列表欄：保留原欄 ID。
- 新欄插在兩欄間：取前後欄排序值的中間值。
- 新欄插在最前：以前方排序值 `0` 與下一欄取中間值。
- 新欄插在最後：使用前一欄排序值加 `65536`。
- 服務層依目標欄、排除來源後的列表計算 `position`，一併送出三個欄位。

`__preview__` 只是投影用的臨時欄 ID，不能保存到後端。落點與動畫調整通常不需要新增 migration，但這項多列表分欄功能本身已依賴既有的自訂 List 欄位與 migrations；不能據此推論未修改的官方 image 一定相容。

## 10. 適用範圍與維護限制

- 自訂二維判定用於非 `SNAP` 的 List 拖曳；須具備看板編輯者權限並啟用編輯模式，且列表已保存、未開啟名稱編輯。
- 鍵盤 `SNAP` 模式使用套件提供的目標欄與索引，未套用上述水平新欄判定。
- 卡片移動仍使用原有卡片拖曳流程，不使用 List 的分欄規則。
- 頁面捲動以 `window.scrollX/Y` 換算；如果改成內層容器捲動，需另行補償容器位移。
- 拖曳期間的尺寸與目標位置沿用開始時快照；即時新增列表、改變高度或調整視窗尺寸並未在此流程重新建立快照。
- CSS 欄寬、左右 margin、垂直 gap 與幾何運算中的 `8/16` 必須同步修改。

## 11. 回歸測試清單

修改後至少檢查：

- 同欄兩個以上 List 可向上、向下交換，且不同高度也正確。
- 跨欄加入頂部、中間、底部，卡片內容不變。
- 從多列表欄拆出，能插入最左、兩欄之間及最右。
- 單列表欄向左、向右移動，尤其向右不得反而落在目標左側。
- 回到原槽位不額外推開右側欄，不產生多餘空欄。
- 接近結合／插入邊界時不持續閃動切換。
- 放開後與最後預覽一致，不被回彈動畫改成結合。
- List 頂邊略高於看板但仍有重疊時，仍能向上排序。
- 無效範圍放開及 Escape 取消不保存。
- 重新整理後，欄順序與欄內順序仍正確。
- 橫向捲動、觸控、鍵盤與原有卡片拖曳分別驗證。

從專案根目錄執行：

```bash
npm run client:test -- --runInBand drag-layout.test.js
npm run client:lint
```

目前幾何單元測試涵蓋中線判定、中間／右側拆欄、原槽位、防抖與快照不變性；它們不能代替真實瀏覽器對事件時序、動畫及後端保存的驗證。瀏覽器測試請使用臨時看板，不移動或刪除使用者既有資料。
